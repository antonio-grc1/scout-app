# Tesorería (`backend/src/tesoreria`)

## Overview
Manages the financial, accounting, fee collection, family discount, cash/bank ledger, income/expense, and fundraising event subsystems of the scout group. Exposes REST endpoints and transactional domain logic for monthly fee plans (`PlanCuotaMensual`), fee concepts (`ConceptoCuota`), member charges (`CargoMiembro`), payments and allocations (`Pago`, `PagoImputacion`), member credit balances (`saldoAFavor`), sibling/family groups (`GrupoFamiliar`), financial accounts (`CuentaFinanciera`), accounting categories (`RubroContable`), operational expenses (`Gasto`), manual incomes and ledger movements (`MovimientoFinanciero`), income statements (`CuadroResultados`), and fundraising/ticketed events with QR ticket validation (`Evento`, `ItemEvento`, `PedidoEvento`, `DetallePedidoEvento`, `TicketEvento`).

## Invariants
- `[tesoreria.dto.ts:montoDecimal]` / `[tesoreria.dto.ts:montoNoNegativo]` — Monetary fields are capped at `99999999.99` (`> 0` for `montoDecimal`, `>= 0` for `montoNoNegativo`).
- `[tesoreria.dto.ts:RegistrarPagoSchema]` / `[tesoreria.dto.ts:AplicarSaldoAFavorSchema]` — `imputaciones` cannot contain duplicate `cargoId` entries.
- `[tesoreria.dto.ts:CrearPedidoEventoSchema]` / `[tesoreria.dto.ts:ActualizarPedidoEventoSchema]` — Order `items` must contain at least 1 item and cannot contain duplicate `itemId` entries.

- `[tesoreria.service.ts:TesoreriaService.vincularHermano]` / `[tesoreria.service.ts:TesoreriaService.desvincularHermano]` — Rejects linking a user to themselves or to a sibling already in the same `grupoFamiliarId` (`BadRequestException`); if unlinking leaves `<= 1` members in a `GrupoFamiliar`, the sole remaining member is also unlinked (and recalculated) and the `GrupoFamiliar` record is deleted.

- `[tesoreria.service.ts:TesoreriaService.registrarPago]` / `[tesoreria.service.ts:TesoreriaService.aplicarSaldoAFavor]` — Forbids `alcance.tipo === 'PROPIO'`; requires `montoTotalRedondeado >= max(0, sumaImputaciones - saldoAAplicar) - 0.001`; enforces atomic `usuario.saldoAFavor >= saldoAAplicar`; requires every imputed charge to belong to the target user or the same `grupoFamiliarId`, not be `ANULADO` or `PAGADO`, and `imp.monto <= saldoPendiente + 0.001`; validates that `cuentaId` matches `TipoCuenta.CAJA_EFECTIVO` for `EFECTIVO` or `TipoCuenta.BANCO` for `TRANSFERENCIA`.
- `[tesoreria.service.ts:TesoreriaService.revertirPago]` — Requires any linked `MovimientoFinanciero` account to be active (`cuenta.activa`) and have sufficient available balance (`saldoDisponible >= impactoEgreso - 0.001`) before deleting movements and reverting the payment.
